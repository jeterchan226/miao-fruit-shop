Ticket: #43

## Why

後台訂單列表查詢的每個篩選條件（訂單狀態、訂單來源、`created_from`、`created_before`、關鍵字、訂單編號）都要分別套用到計算總筆數與取列表兩個查詢，已重複六組。之後新增篩選時只要漏改一邊，總筆數就會與列表內容不一致，而現有測試未涵蓋這種情況。

## What Changes

- 篩選條件只定義一次，同一組條件同時用於總筆數與列表查詢。
- 補上驗收情境，鎖定「多個條件同時成立」與「總筆數與列表一致」這兩個既有行為。
- 純重構：API 參數、回應格式與篩選結果皆不變。

## User Stories

1. 身為管理員，我想要列表總筆數永遠與篩選結果一致，以便分頁與筆數顯示可信。
2. 身為開發者，我想要篩選條件只寫一次，以便新增篩選時不會漏改其中一個查詢。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `admin-orders`：「訂單列表篩選」補上多條件同時成立與總筆數一致的情境；行為不變，僅把既有行為寫成驗收條件。

## Impact

- 後端訂單 repository 的列表查詢；service、route、schema 與前端不動。
- 無 migration、無 API 變更。
- 後續 #42 狀態 chip 計數若決定隨篩選變動，可沿用這組條件。
