Ticket: #82

## Why

顧客下單的 API 不需登入，回應若帶到顧客個資、LINE 身份或轉帳資訊，等於對外洩漏。目前回應確實不含這些資料，但只靠回應結構的現況維持，測試只擋了庫存數量；日後有人在回應加欄位，不會有測試失敗。

## What Changes

- 把「顧客下單」回應的內容寫成明確清單：頂層只有訂單編號、狀態、訂單品項、金額與成立時間，訂單品項只有規格識別、商品名稱、規格名稱、單價、數量與小計。
- 補一個 HTTP API 測試鎖住這份清單，回應多出任何欄位都會失敗。
- 不改 API 行為與前端；這是把既有行為鎖進規格與測試。

## User Stories

1. 身為店家，我想要公開下單回應的內容有測試把關，以便日後改動不會把顧客資料或轉帳資訊洩漏出去。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `storefront-checkout`: 「顧客下單」的「公開回應不含後台欄位」情境改為明列回應內容，可直接驗證。

## Impact

- 後端測試：顧客下單的 HTTP API 測試多一個案例。
- 規格：`storefront-checkout` 的「顧客下單」情境文字。
- 無 API、資料庫、前端或部署變更。
