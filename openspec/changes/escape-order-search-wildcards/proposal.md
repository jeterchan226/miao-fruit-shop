Ticket: #91

## Why

後台訂單列表的關鍵字把管理員輸入的文字直接放進資料庫的模式比對。`%` 與 `_` 成了萬用字元，反斜線成了跳脫字元：輸入 `%` 會列出全部訂單，輸入 `_` 會比對任一字元，與規格的「部分比對」不符。

## What Changes

- 關鍵字中的 `%`、`_`、`\` 一律視為一般字元，比對四個欄位時只找字面上包含該文字的訂單。
- 不分大小寫的部分比對、比對欄位與其他篩選條件不變。

## User Stories

1. 身為管理員，我想要搜尋 `%` 或 `_` 時只找到字面含有這些符號的訂單，以便搜尋結果符合我輸入的文字。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `admin-orders`: 「訂單列表篩選」的關鍵字比對明定 `%`、`_`、`\` 為一般字元。

## Impact

- 後台 API `GET /api/admin/orders` 的 `q` 參數：含 `%`、`_`、`\` 的查詢結果改變，參數與回應格式不變。
- 後端訂單 repository 的關鍵字條件。
- 無 migration，前端不變。
- 與 #43 改同一段查詢組裝與同一條 requirement，須在其後實作。
