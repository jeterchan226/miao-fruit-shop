## ADDED Requirements

### Requirement: 訂單測試資料集中定義
後端測試 SHALL 透過同一份定義取得訂單測試資料，測試檔 MUST NOT 自行列出訂單的完整欄位。

#### Scenario: 訂單新增必填欄位只改一處
- **WHEN** 訂單新增一個必填欄位，並只在集中定義補上預設值
- **THEN** 所有建立訂單的測試不需修改即可建立訂單

#### Scenario: 測試覆寫訂單欄位
- **WHEN** 測試指定訂單的部分欄位（例如訂單狀態或金額）
- **THEN** 取得的訂單使用指定值，其餘欄位使用預設值

#### Scenario: 指定不存在的欄位
- **WHEN** 測試指定訂單沒有的欄位名稱
- **THEN** 建立失敗並回報錯誤，不靜默忽略

### Requirement: 規格測試資料集中定義
訂單相關測試 SHALL 透過同一份定義取得規格與其所屬商品的測試資料。

#### Scenario: 取得已寫入資料庫的規格
- **WHEN** 測試要求一個已存在的規格
- **THEN** 取得已寫入資料庫、具有 id 且屬於某商品的規格

#### Scenario: 同一測試建立多個規格
- **WHEN** 測試要求同一商品下的多個規格
- **THEN** 這些規格屬於同一商品，且順序與要求時相同

### Requirement: 含訂單品項的訂單
測試 SHALL 能以「規格、數量、下單價」描述訂單品項，取得已寫入資料庫的訂單。

#### Scenario: 訂單金額由訂單品項算出
- **WHEN** 測試以數個（規格、數量、下單價）建立訂單
- **THEN** 訂單品項的小計與訂單的小計、總金額皆等於下單價乘以數量的加總

#### Scenario: 測試覆寫訂單金額
- **WHEN** 測試同時指定訂單金額
- **THEN** 訂單使用指定金額，訂單品項不受影響

### Requirement: 工廠不結束交易
建立測試資料 MUST NOT 自行 commit，交易的結束由測試決定。

#### Scenario: 交易回滾的測試
- **WHEN** 測試透過工廠寫入資料後結束，且該測試的交易被回滾
- **THEN** 資料不留在資料庫，不影響其他測試

#### Scenario: 自行 commit 的並行測試
- **WHEN** 並行測試以工廠建立資料後自行 commit
- **THEN** 其他連線可讀到該資料，並可由該測試自行清除

### Requirement: 重構不改變驗證內容
導入集中定義 MUST NOT 改變既有測試所驗證的行為。

#### Scenario: 既有測試維持通過且斷言不變
- **WHEN** 既有測試改用集中定義
- **THEN** 這些測試全數通過，且斷言與斷言的期望值未被修改
