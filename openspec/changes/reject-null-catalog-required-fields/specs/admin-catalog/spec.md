## ADDED Requirements

### Requirement: 商品部分更新的 null 處理

商品的部分更新 MUST 在必填欄位（名稱、描述、產季、上架狀態）明確送 `null` 時回傳 422，且整筆請求不寫入；選填欄位（圖片、標籤、標籤顏色）明確送 `null` SHALL 清空該欄位。

#### Scenario: 商品必填欄位送 null

- **WHEN** 管理員修改商品時對名稱、描述、產季或上架狀態送 `null`
- **THEN** 系統回傳 422，商品資料不變

#### Scenario: 商品請求同時帶合法欄位

- **WHEN** 管理員修改商品的請求同時帶合法的產季與值為 `null` 的名稱
- **THEN** 系統回傳 422，產季與名稱皆不變

#### Scenario: 商品選填欄位送 null

- **WHEN** 管理員修改商品時對標籤送 `null`
- **THEN** 標籤被清空，其他欄位不變

### Requirement: 規格部分更新的 null 處理

規格的部分更新 MUST 在必填欄位（名稱、容量說明、價格、庫存、低庫存門檻、排序值、上架狀態、包裝類型）明確送 `null` 時回傳 422，且整筆請求不寫入；選填欄位（備註）明確送 `null` SHALL 清空該欄位。

#### Scenario: 規格必填欄位送 null

- **WHEN** 管理員修改規格時對任一必填欄位送 `null`
- **THEN** 系統回傳 422，規格資料不變

#### Scenario: 規格請求同時帶合法欄位

- **WHEN** 管理員修改規格的請求同時帶合法的庫存與值為 `null` 的價格
- **THEN** 系統回傳 422，庫存與價格皆不變

#### Scenario: 規格備註送 null

- **WHEN** 管理員修改規格時對備註送 `null`
- **THEN** 備註被清空，其他欄位不變

## REMOVED Requirements

### Requirement: 必填欄位送 null 為伺服器錯誤

**Reason**: 這是把既有缺陷記錄成需求；請求內容有誤應回 422，與訂單的後台修改一致。

**Migration**: 由「商品部分更新的 null 處理」與「規格部分更新的 null 處理」取代。後台前端不送此類請求，無需調整。
