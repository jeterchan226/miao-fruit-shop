# admin-catalog Specification

## Purpose

描述管理員維護商品與規格的能力：查看含庫存與下架資料的清單、修改商品資料、新增修改與刪除規格、調整規格排序，以及初次部署時以指令建立初始商品。商店維持單一商品多規格的設計。

## Requirements

### Requirement: 後台商品 API 需管理員身分

系統 MUST 對所有後台商品與規格 API 要求有效的管理員 token，否則回傳 401。

#### Scenario: 未帶 token

- **WHEN** 未帶 token 呼叫後台商品 API
- **THEN** 系統回傳 401

### Requirement: 後台商品清單

系統 SHALL 回傳全部商品與規格，包含已下架者，並附庫存數量、低庫存門檻、排序值、上架狀態與庫存狀態。

#### Scenario: 含已下架規格

- **WHEN** 管理員查詢商品清單
- **THEN** 回應包含已下架的商品與規格及其庫存數量

### Requirement: 修改商品

系統 SHALL 允許管理員部分更新商品的名稱、描述、圖片、產季、標籤與上架狀態，只更新請求中有帶的欄位；商品不存在時回傳 404，未定義的欄位回傳 422。

#### Scenario: 更新商品欄位

- **WHEN** 管理員修改商品產季
- **THEN** 產季更新，其他欄位不變

#### Scenario: 商品不存在

- **WHEN** 管理員修改不存在的商品
- **THEN** 系統回傳 404

### Requirement: 新增規格

系統 SHALL 允許管理員在商品下新增規格並回傳 201；低庫存門檻預設 3、排序值預設 0、預設為箱裝且上架。商品不存在時回傳 404，未定義的欄位回傳 422。

#### Scenario: 使用預設值

- **WHEN** 管理員新增規格時未帶低庫存門檻與包裝類型
- **THEN** 規格的低庫存門檻為 3，包裝類型為箱裝

#### Scenario: 回傳同組圖片

- **WHEN** 新增的規格所屬包裝類型已有相片組
- **THEN** 回應的規格圖片為該相片組

### Requirement: 修改規格

系統 SHALL 允許管理員部分更新規格的名稱、容量說明、價格、庫存、低庫存門檻、備註、排序值、上架狀態與包裝類型，只更新請求中有帶的欄位；規格不存在時回傳 404，未定義的欄位回傳 422。

#### Scenario: 調整價格

- **WHEN** 管理員修改規格價格
- **THEN** 價格更新，既有訂單品項的下單價不變

#### Scenario: 變更包裝類型

- **WHEN** 管理員變更規格的包裝類型
- **THEN** 規格的圖片改為新包裝類型的相片組

#### Scenario: 下架規格

- **WHEN** 管理員把規格的上架狀態改為否
- **THEN** 該規格不再出現在公開商品查詢，既有訂單品項不受影響

### Requirement: 必填欄位送 null 為伺服器錯誤

商品或規格的部分更新 SHALL 接受欄位值為 `null`，不在請求驗證階段阻擋；必填欄位送 `null` 時更新失敗並回傳伺服器錯誤。

#### Scenario: 規格名稱送 null

- **WHEN** 請求對規格名稱送 `null`
- **THEN** 更新失敗，系統回傳 500

### Requirement: 刪除規格

系統 SHALL 允許管理員永久刪除規格並回傳 204，規格不存在時回傳 404；既有訂單品項 MUST 保留其快照內容。後台 SHALL 在刪除前要求確認。

#### Scenario: 刪除規格

- **WHEN** 管理員確認刪除規格
- **THEN** 規格從商品清單消失

#### Scenario: 已有訂單的規格

- **WHEN** 被刪除的規格存在於既有訂單
- **THEN** 訂單品項的名稱、下單價與數量維持不變

### Requirement: 規格排序

後台 SHALL 依包裝類型分組列出規格，並提供在同組內上移或下移，以交換排序值的方式保存。

#### Scenario: 上移規格

- **WHEN** 管理員把規格往上移
- **THEN** 該規格與上一個規格交換順序

#### Scenario: 位於邊界

- **WHEN** 規格已是同組第一個
- **THEN** 上移按鈕不可點選

### Requirement: 建立初始商品

系統 SHALL 提供管理指令建立初始商品甘露梨與三個規格：2 粒精緻禮盒、5 台斤家庭箱、10 台斤大箱；商品已存在時 MUST 中止並提示，不重複建立。

#### Scenario: 首次執行

- **WHEN** 資料庫沒有初始商品時執行指令
- **THEN** 建立甘露梨與三個規格，其中 2 粒精緻禮盒為兩粒裝

#### Scenario: 重複執行

- **WHEN** 初始商品已存在時執行指令
- **THEN** 指令中止，資料不變
